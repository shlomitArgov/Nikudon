# Phase 260903-b80 Plan 01: StagePlayer Drill UX Iteration + Audio Fix Summary

**Fixed the Bet-consonant audio carrier mismatch, and rewrote StagePlayer's single-trial mastery flow into a navigable-history drill with gesture-unlocked auto-play, icon-only feedback, auto-advance on correct, and always-available back/forward navigation.**

## Accomplishments

- Regenerated `a.wav`/`i.wav` as pure vowels on an Alef carrier via `say -v Carmit`, so the heard sound matches the displayed Alef-based niqqud symbol (no more leading "b" onset)
- Added a module-level `unlockAudio()` export in `useAudioPlayer.ts`, wired into Home's start tap, so the gesture that enters the stage unlocks the shared `AudioContext` for the first trial's auto-play (iOS-safe)
- Capped `generateTrial`'s option count at 2-3 (was 3-4), keeping the engine pure
- Rewrote `StagePlayer` around a `trials`/`currentIndex`/`answers` history: each new trial auto-plays exactly once; a correct tap flashes green and auto-advances after ~1s; a wrong tap shows a red X badge and does not advance, so the child can retry or replay; back/forward icon buttons are always present, with forward past the last trial generating a new one and back revisiting prior trials with their remembered answer state
- Removed the Hebrew feedback pop-up overlay, the blocking `alert()` mastery celebration, and the session-total counters, replacing them with icon-only feedback and a per-page position indicator
- (Follow-up, orchestrator-applied) Replaced the "שלב: stage-1" text header with a number-only corner badge (`stage.id` → "1"), keeping the drill screen text-free — commit `b748efe`

## Decisions Made

- Removed mastery/progress tracking and the blocking `alert()` celebration from StagePlayer entirely for this iteration (see key-decisions in frontmatter for full rationale). `checkMastery`/`recordTrialResult`/`createStageProgress` remain defined and pure in `src/engine/stageRunner.ts` — just unused by StagePlayer now — so a future task can reintroduce an icon-based end-of-stage celebration without touching the engine.
- Replaced the monotonic session-total progress counters (ניסיונות/נכונים/דיוק) with a per-page position indicator (`current index + 1 / trials.length` + a check/X status icon for the currently-viewed trial), since the drill no longer has a single linear "session total" concept once back/forward navigation is always available.
- Auto-play effect depends on the `currentTrial` object reference (not just its `id`) plus `isReady`; because `trials` is only ever updated immutably and `currentTrial = trials[currentIndex]`, the object reference stays stable across unrelated re-renders (e.g. when `answers` changes), so this does not cause repeat auto-plays — the `lastAutoPlayedTrialId` ref guard is a second line of defense.
