<task type="auto">
  <name>Task 3: Rewrite StagePlayer as a navigable-history drill with auto-play, auto-advance, and icon-only feedback (C2, C3, C4, C5)</name>
  <files>src/pages/StagePlayer.tsx, src/pages/StagePlayer.css</files>
  <action>
Rewrite the drill's state model and interaction. Keep src/engine/stageRunner.ts PURE — all history, index, and answered-state lives here in component state; use only generateTrial and the Trial type from the engine. Remove the mastery/progress machinery entirely (see mastery decision below), so the only engine import used is generateTrial (+ type Trial). After editing, remove EVERY now-unused import and state variable, since tsc strict (noUnusedLocals/noUnusedParameters) fails the build otherwise — the compiler will name each leftover.

State model (all in StagePlayer component state):
- `trials: Trial[]` — ordered history of generated trials.
- `currentIndex: number` — index into `trials`.
- `answers` — a parallel array the same length as `trials`, each entry either null (unanswered) or an object holding the selected group id and whether it was correct. Define a small local interface for the answer entry with a selectedGroupId (NikudGroupId) field and an isCorrect (boolean) field.
- `usedSyllables: Set<string>` — keep for syllable dedup passed to generateTrial.
- An `advanceTimer` ref (number | null) for the correct-answer auto-advance timeout, plus a `lastAutoPlayedTrialId` ref (string | null) to auto-play each trial exactly once.

Init effect (depends on stage.id only, keep the existing eslint-disable for exhaustive-deps): generate the first trial, set trials to a single-element array, currentIndex to 0, answers to a single-element array holding null, and add the trial's audioSyllable to usedSyllables.

Auto-play (C2): add an effect depending on the current trial's id and on `isReady` (from useAudioPlayer). When `isReady` is true and there is a current trial whose id differs from `lastAutoPlayedTrialId.current`, call `play(currentTrial.correctGroupId)` and set `lastAutoPlayedTrialId.current` to that id. This plays each trial exactly once — the first trial fires when preload flips isReady true (context already unlocked by Home's start tap), and every navigated-to new trial fires on id change. play() is already fail-soft (console.warn, never throw) when a clip is missing; do not add throwing behavior.

Option select handler (C3, C4, C5): accept a groupId. Guard only on "no current trial" — do NOT gate on already-answered, because returning to a past trial must still allow re-selecting and re-hearing. First clear any pending auto-advance timer. Compute isCorrect = groupId === currentTrial.correctGroupId. Update the answers array immutably at currentIndex with the new answer entry (this also covers re-answering a revisited trial — overwrite, never append, so nothing is double-counted). If correct, start a single setTimeout of ~1000ms (within the 800-1200ms range) stored in advanceTimer that calls the forward handler; if wrong, do nothing further (no auto-advance — the child retries or replays).

Forward handler (C5): clear any pending advance timer. If currentIndex is before the last trial, increment currentIndex (revisit an already-seen trial). If currentIndex is the last trial, generate a NEW trial via generateTrial(stage, usedSyllables), append it to trials, append null to answers, add its audioSyllable to usedSyllables, and set currentIndex to the new last index.

Back handler (C5): clear any pending advance timer. If currentIndex > 0, decrement it; otherwise no-op.

Cleanup: add an effect returning a cleanup that clears advanceTimer on unmount, so no state is set after unmount.

Render (icon/sound only — no reading required):
- Header: keep the existing stage id heading. Replace the Hebrew "ניסיונות/נכונים/דיוק" counters block with a PER-PAGE indicator reflecting the CURRENTLY-VIEWED position: show position as current index + 1 over trials.length, plus a status icon for the current trial derived from answers[currentIndex] — a check mark if correct, an X mark if wrong, and a neutral mark (or nothing) if unanswered. Do NOT show a monotonic session total.
- Play button: keep the existing round play button, calling play(currentTrial.correctGroupId) so the child can replay on demand.
- Options: map currentTrial.options to buttons. Buttons are ALWAYS enabled (remove the disabled-on-selected gating) so revisited trials can be re-answered. For each option, if answers[currentIndex] is set AND this option equals the recorded selectedGroupId, apply the correct class when that answer was correct or the incorrect class when it was wrong. Only style the SELECTED option (do not auto-reveal the correct answer on a wrong tap — the child should try again / listen again).
- Navigation: add a back icon button and a forward icon button available at ALL times, laid out sensibly for RTL (the container is already direction: rtl). Give each an aria-label ("Previous" / "Next"). Disable the back button when currentIndex is 0; the forward button is always enabled (it generates a new trial at the end).
- DELETE the answer-feedback pop-up overlay JSX entirely — the conditional block that renders a large check/X badge with Hebrew "correct/incorrect" wording — and DELETE the standalone manual next-button block (forward navigation replaces it).

StagePlayer.css: remove the CSS rules paired with the deleted pop-up overlay (the overlay wrapper, the popup container, the popup emoji, the popup text, and the correct/incorrect popup color variants) and the standalone popIn/bounce keyframes only used by them. Rework the option "incorrect" style into a clear wrong state: red background/border with a corner X badge rendered via an ::after on the incorrect option (position the option-button relative and place the badge in a corner so it does not reorder the Hebrew label under bidi). Keep/rework the option "correct" style as a short green highlight (the existing green + pulse is fine) and optionally add a matching corner check badge for icon reinforcement. Add small styles for the two navigation icon buttons and the per-page position indicator.

Mastery decision (flagged per constraint): REMOVE the blocking mastery-celebration browser pop-up and all mastery/progress tracking from StagePlayer for this iteration. Rationale: (a) it rendered Hebrew text and used a blocking browser pop-up, both of which violate the pre-literate, icon-only, no-blocking-pop-up ethos in CLAUDE.md; (b) with always-available forward navigation that generates unlimited new trials, there is no natural end-point to celebrate; (c) a scheduled celebration would race the correct-answer auto-advance. A proper icon-based end-of-stage celebration is out of scope for this UX-iteration task and can be a future change. Dropping this also removes the checkMastery/recordTrialResult/createStageProgress/StageProgress imports from StagePlayer (engine functions stay defined and pure — just unused here).
