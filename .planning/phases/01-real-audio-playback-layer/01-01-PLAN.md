<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| build-time assets -> client runtime | `.wav` clips are bundled at build via `import.meta.glob`; no audio source is supplied at runtime by a user or remote origin |
| service worker precache -> browser fetch | Workbox precaches the built clips; runtime `fetch()` resolves from that cache, not an attacker-reachable network path |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Tampering | URL passed to `fetch()`/`decodeAudioData` in `useAudioPlayer.ts` | low | accept | `getAudioUrl` is keyed by the closed union `NikudGroupId` and returns only build-time `import.meta.glob` literal URLs; no user- or remote-controlled string can reach `fetch()`. No runtime input-validation code is warranted (RESEARCH Security Domain). |
| T-01-02 | Denial of Service | malformed/oversized clip crashes the tab during decode | low | mitigate | `decodeAudioData` is wrapped in try/catch with fail-soft `console.warn` (D-03); a bad clip degrades to silence, never a crash or blocking dialog. |
| T-01-SC | Tampering | npm/pip/cargo installs | low | accept | This phase installs ZERO new runtime packages (RESEARCH Package Legitimacy Audit: N/A — native Web Audio API only); no new supply-chain surface is introduced. |

ASVS level 1, block-on threshold = high. All threats above are low severity — none block. This is honestly a near-empty attack surface: a static-asset-playback feature in a client-only PWA with no auth, no backend, no sessions, and a closed-union lookup key (RESEARCH Security Domain conclusion).
</threat_model>
