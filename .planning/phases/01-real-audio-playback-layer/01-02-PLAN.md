<objective>
Prove AUDIO-03 on real hardware: the audio path built in `01-01` plays reliably on a real iPad (Safari) and a real Android tablet, including inside the installed/standalone PWA, from the very first tap. This is the phase's mandated acceptance gate (ROADMAP Phase 1 notes; PITFALLS.md "never ship audio without real-device testing") and is the true end-to-end proof that the MVP slice works — desktop build passing is necessary but not sufficient for the iOS synchronous-gesture-unlock and offline-precache behaviors.

Purpose: Desktop Chrome cannot surface the iOS Safari first-tap gesture-unlock race or confirm the Workbox precache serves the clips offline in a standalone PWA. Only real devices can.
Output: A recorded pass/fail on real devices; on failure, specific reproduction notes to drive a gap-closure replan.
</objective>

  <how-to-verify>
    Serve and test on real devices using the commands recorded in the Task 1 SUMMARY.

    A. In-browser-tab test (both devices):
      1. Start the LAN preview (`npm run build && npm run preview -- --host`).
      2. On a real iPad in Safari, open `http://<lan-ip>:<port>` and navigate into a stage (drill screen).
      3. As the VERY FIRST interaction of the session, tap the play button (the speaker icon). Expected: you hear the syllable clip on that first tap (no silent first tap). This first-tap case is the iOS synchronous-gesture-unlock check.
      4. Tap the play button rapidly 5+ times in succession. Expected: the clip replays each time, cleanly, with no audible lag and no missed taps.
      5. Repeat steps 2-4 on a real Android tablet in Chrome.

    B. Installed / standalone PWA test (both devices), using the HTTPS URL from the SUMMARY:
      6. Open the HTTPS URL, use the browser's "Add to Home Screen" / install prompt.
      7. Launch the installed app from the home screen (standalone, no browser chrome).
      8. Navigate to a stage and repeat the first-tap + rapid-repeat checks (steps 3-4). Expected: audio plays inside the standalone PWA, including on the first tap.
      9. Optional offline confirmation: put the device in airplane mode, relaunch the installed PWA, tap play. Expected: the precached clip still plays (Workbox offline precache).

    Report "approved" only if steps 3, 4, 5, and 8 all pass on BOTH device families. If any leg fails, report exactly which device, which step, and the observed behavior (e.g. "iPad, step 3, first tap silent, second tap plays" — that is the classic preload-race signature).

    If no physical iPad and/or Android tablet is available and no device-farm access can be arranged, do NOT silently approve — this is a blocking question for the human per RESEARCH Environment Availability. State that the device is unavailable so the acceptance gate stays open.
