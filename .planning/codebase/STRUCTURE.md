## Directory Purposes

**`src/`:**
- Purpose: All source code (TypeScript + JSX)
- Contains: React components, game logic, content data
- Key files: `main.tsx` (entry), `App.tsx` (router), `pages/` (UI), `content/` (data), `engine/` (logic)

**`src/pages/`:**
- Purpose: Page-level React components routed by React Router
- Contains: Two pages — Home (start screen) and StagePlayer (quiz)
- Key files: `Home.tsx`, `StagePlayer.tsx` plus their CSS files

**`src/content/`:**
- Purpose: Immutable game domain data
- Contains: Stage progression definitions, vowel mark metadata, Hebrew alphabet reference
- Key files: `stages.ts` (5 learning stages), `nikudGroups.ts` (5 vowel groups), `letters.ts` (alphabet)
- Characteristics: No functions (except lookup helpers), only const arrays and TypeScript types

**`src/engine/`:**
- Purpose: Game mechanics and state management logic
- Contains: Pure functions for trial generation, result recording, mastery checking
- Key files: `stageRunner.ts` (400+ lines; core business logic)
- Characteristics: No React dependencies; functions are deterministic (except Math.random())

**`public/`:**
- Purpose: Static assets served as-is
- Contains: PWA manifest, favicon, app icons
- Not in source control except manifest configuration (icons exist but not tracked)

**`dist/`:**
- Purpose: Build output directory
- Generated by: `npm run build` (Vite compilation)
- Ignored in git

## Key File Locations

**Entry Points:**
- `index.html` — HTML document; defines `<div id="root">` and loads `/src/main.tsx`
- `src/main.tsx` — React app bootstrap; renders App component into DOM
- `src/App.tsx` — React Router setup; defines `/`, `/stage/:stageId`, `/stage` routes

**Configuration:**
- `vite.config.ts` — Build tool setup; Vite + React plugin + PWA plugin configuration
- `tsconfig.json` — TypeScript strict mode (noUnusedLocals, noUnusedParameters, strict: true)
- `.eslintrc.cjs` — Linting rules (ESLint recommended + TypeScript + React hooks)
- `package.json` — Dependencies and scripts (dev, build, preview, lint)

**Core Logic:**
- `src/engine/stageRunner.ts` — Exports 5 key functions:
  - `generateTrial()` — Creates Trial with random options
  - `recordTrialResult()` — Updates StageProgress with result
  - `checkMastery()` — Determines if stage is complete (80% accuracy after 8+ trials)
  - `createStageProgress()` — Initializes progress tracker
  - TypeScript interfaces: Trial, TrialResult, StageProgress, MasteryConfig

**Game Data:**
- `src/content/stages.ts` — 5 Stage definitions (stage-1 through stage-5); each introduces one vowel and reviews previous vowels
- `src/content/nikudGroups.ts` — 5 NikudGroup definitions (a, e, i, o, u); maps group ID to label, member marks, and example syllables
- `src/content/letters.ts` — Hebrew alphabet (22 letters) used for reference and future audio generation

**Presentation:**
- `src/pages/Home.tsx` — Start screen with title "ניקודון" and play button; calls `getFirstStage()` and navigates to `/stage/{id}`
- `src/pages/StagePlayer.tsx` — Quiz interface; shows current trial audio button, option buttons, progress bar, and feedback popups
- CSS files: Global (`index.css`, `App.css`), scoped to components (`Home.css`, `StagePlayer.css`)

## Naming Conventions

**Files:**
- Component files: PascalCase with .tsx extension (e.g., `Home.tsx`, `StagePlayer.tsx`)
- Logic files: camelCase with .ts extension (e.g., `stageRunner.ts`)
- Style files: Match component name (e.g., `Home.css` pairs with `Home.tsx`)
- Config files: PascalCase with .ts/.cjs extension (e.g., `vite.config.ts`)

**Directories:**
- Page components: `src/pages/` (lowercase)
- Game logic: `src/engine/` (lowercase)
- Game data: `src/content/` (lowercase)
- No abbreviations; full words preferred

**Functions:**
- Pure functions: camelCase (e.g., `generateTrial`, `checkMastery`, `recordTrialResult`)
- React components: PascalCase (e.g., `Home`, `StagePlayer`)
- Lookup/getter functions: camelCase with get prefix (e.g., `getStage`, `getNikudGroup`, `getAllNikudGroupIds`)

**Variables/Constants:**
- Constants: camelCase or UPPER_SNAKE_CASE (mostly camelCase in this codebase)
- Component state: camelCase (e.g., `currentTrial`, `usedSyllables`, `progress`)
- Type names: PascalCase (e.g., `Stage`, `Trial`, `StageProgress`)

**Identifiers in Data:**
- Stage IDs: kebab-case (e.g., `stage-1`, `stage-2`)
- Nikud group IDs: lowercase single letter (e.g., `a`, `e`, `i`, `o`, `u`)
- Trial IDs: kebab-case with timestamp (e.g., `trial-1234567890123-0.456`)

## Where to Add New Code

**New Feature (e.g., stage progression to next stage):**
- Primary code: `src/pages/StagePlayer.tsx` (add button and navigation logic)
- Supporting logic: `src/engine/stageRunner.ts` (if feature needs game mechanics)
- Data: `src/content/stages.ts` (if adding new stages)
- Tests: `src/pages/StagePlayer.test.tsx` (if test infrastructure added)

**New Stage:**
- Add Stage object to `src/content/stages.ts` array (follow id pattern: stage-6, stage-7, etc.)
- Update `src/content/nikudGroups.ts` if introducing new vowel sounds
- No UI changes required (dynamic)

**New Vowel/Nikud Group:**
- Add NikudGroup to `src/content/nikudGroups.ts` array (follow id pattern: f, g, etc.)
- Update `src/content/stages.ts` to reference new group in review lists
- Audio playback logic in StagePlayer handles automatically via group ID

**Utility Function:**
- Lookup/mapping functions: `src/content/` (e.g., getStage, getNikudGroup)
- Game logic: `src/engine/stageRunner.ts` (e.g., generateTrial, recordTrialResult)
- React hooks/helpers: Could go in `src/pages/` or new `src/hooks/` directory (not yet created)

**New Page Route:**
- Add Route in `src/App.tsx` (BrowserRouter → Routes → new Route element)
- Create page component in `src/pages/` (e.g., `Results.tsx`, `Settings.tsx`)
- Add page CSS file alongside component (e.g., `Results.css`)

**Global Styles:**
- CSS variables and base defaults: `src/index.css`
- Layout/container styles: `src/App.css`
- Component-specific styles: Paired CSS file in component directory

## Special Directories

**`dist/`:**
- Purpose: Build output
- Generated: Yes (by `npm run build`)
- Committed: No (in .gitignore)
- Contains: Minified HTML, CSS, JavaScript for production deployment
- Clear before rebuild: Yes (Vite overwrites)

**`node_modules/`:**
- Purpose: Installed npm packages
- Generated: Yes (by `npm install`)
- Committed: No (in .gitignore)
- Lockfile: `package-lock.json` (tracks exact versions)

**`.planning/`:**
- Purpose: GSD project management (milestones, phases, codebase docs)
- Committed: Yes
- Subdir: `.planning/codebase/` contains ARCHITECTURE.md, STRUCTURE.md, etc.

**`public/`:**
- Purpose: Static web assets (favicon, PWA icons, manifest)
- Served: Yes (Vite copies to dist during build)
- Can include: PNG images, SVG, manifest.json
- Note: Manifest configured in `vite.config.ts` rather than in public/ directory

**`.vite/`:**
- Purpose: Vite development server cache
- Generated: Yes (by `npm run dev`)
- Committed: No (in .gitignore)
- Can delete safely: Yes
